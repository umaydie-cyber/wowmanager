WowManager 分阶段开发提示词
=============================

使用方式
--------
下面每段可单独复制给编码助手。必须按顺序完成；每一步先阅读前一步的代码和 docs，保留已有改动，不重置、不删除用户文件。除非任务明确要求，不要引入后端、在线账号、付费或第三方版权素材。每一步完成后运行对应验证命令，并简要报告改动文件、验证结果和仍未实现的范围。

项目总原则
----------
- 使用 TypeScript 严格模式、Vite、React、Phaser 3、Zustand、Zod、IndexedDB。
- 目标部署 URL 是 https://umaydie-cyber.github.io/wowmanager/，Vite 的 base 必须是 /wowmanager/。
- React 负责 DOM 面板；Phaser 负责画布地图、精灵、动画。核心规则必须是纯 TypeScript，不能写进 React 组件或 Phaser Scene。
- 规则和数值数据驱动，候选数值集中到 src/game/content 或 src/game/balance；不能在 UI 中写死。
- 游戏为原创像素奇幻作品；使用占位色块或原创资产，不使用第三方游戏素材、名称、音效或角色。
- 每个阶段都更新 README 或相关 docs，保持 npm run lint、npm run test、npm run build 可用。


PROMPT 01 — 初始化和自动部署
------------------------------
在空的 WowManager 仓库中初始化前端工程。先阅读 docs/01-product-design.md 和 docs/02-technical-stack.md，严格按其中技术栈实现。

要求：
1. 用 Vite 创建 React + TypeScript 严格模式工程，配置路径和 Vite base 为 /wowmanager/。
2. 安装并配置 Phaser、Zustand、Zod、idb、Vitest、Testing Library、ESLint、Prettier；不要加入后端或大型 UI 库。
3. 建立文档约定的 src 目录骨架，并创建一个可显示“WowManager / 开始新游戏”的 React 欢迎页。
4. 创建 .github/workflows/deploy-pages.yml：main push 触发，使用 npm ci、npm run build、GitHub Pages 官方 actions 部署 dist。Actions 使用固定版本 SHA 或官方推荐的当前安全配置。
5. 添加 GitHub Pages 部署说明和本地运行命令到 README。
6. 页面在 GitHub Pages 子路径下加载资源正确；不得使用绝对根路径引用静态资产。

验证：npm run lint、npm run test、npm run build。报告每个命令结果。


PROMPT 02 — 可测试的游戏核心和存档
------------------------------------
在现有工程中实现最小可运行的游戏核心与本地存档，不先做精美画面。阅读 docs 中的规则，特别是角色状态机和经验公式。

要求：
1. 定义清晰的 TypeScript 类型：GameState、Hero、Building、Fortress、Inventory、SkillProgress、HeroActivity、SaveFile。
2. 在 src/game/core 中实现纯函数命令和 advance(state, deltaMs, rng)。不得依赖 React、Phaser、浏览器 API 或 Date.now。
3. 实现经验公式 xpToNext(L) = 100 * (floor(L / 50) + 1)，专业上限 300，且为 0/49/50/99/300 等边界编写单元测试。
4. 在 src/game/content 中建立初始帐篷、初级矿坑、初级药圃、健身房及 3 个测试角色配置。所有未确认数值标为候选配置。
5. 用 idb 创建带 schemaVersion 的单存档仓库，实现 Zod 校验、新游戏、保存、加载、导出 JSON、导入 JSON；导入错误时不覆盖现有存档。
6. 用 Zustand 提供命令入口和只读 selector。写一个简单 React 调试面板来创建、保存、加载和显示当前 state 摘要。

验证：补充 Vitest 测试，运行 npm run lint、npm run test、npm run build。


PROMPT 03 — 要塞建造和像素主场景
----------------------------------
在已有可测试核心基础上，实现 8×8 要塞建造和 Phaser 主场景。不要实现战斗。

要求：
1. Phaser 以低分辨率逻辑画布渲染 8×8 网格；使用原创几何像素占位图，不需外部素材。开启 pixelArt/nearest-neighbor 效果。
2. React 中提供建造栏、选中建筑检查器、资源栏和撤销/拆除操作。建造、移动、拆除必须调用核心命令。
3. 实现建筑占地/边界/重叠/资源充足校验，并为每项写核心单元测试。
4. 在新游戏中放置 3 个帐篷、1 个矿坑、1 个药圃、1 个健身房；用可读的默认布局，不要使建筑重叠。
5. 选中格子或建筑时，React 与 Phaser 选择状态同步，但不要让 Phaser 直接修改 Zustand。
6. 保持刷新后从 IndexedDB 恢复布局。

验证：npm run lint、npm run test、npm run build；手工检查 npm run dev 中的放置、移动、拆除和刷新恢复。


PROMPT 04 — 角色自动休息与工作循环
------------------------------------
实现角色在要塞内的移动、休息、采集和锻炼。此阶段是首个核心玩法可玩版本。

要求：
1. 严格实现 docs/01-product-design.md 的状态机和“从自己的帐篷寻找最近 3 个同类设施”的规则。距离用曼哈顿距离，同距按建筑 ID，单次精力周期内每座设施仅处理一次。
2. 精力为 0 时走向自己的帐篷并补满；帐篷可分别设为制造或锻炼偏好。MVP 初始精力上限 30、工作每秒消耗 1 点均从配置读取。
3. 矿坑每轮 3 秒、最多 3 轮、完成一轮得采矿经验 10 和可配置矿石；健身房每轮 5 秒、最多 2 轮、完成一轮得耐力经验 10。精力不足以完成下一整轮时返回帐篷，未完成轮次不结算奖励。
4. 实现可注入 RNG 的矿石星级掉落表，按采矿技能区间加权；测试掉落权重选择、工作次数上限、精力不足和状态转换。
5. Phaser 显示角色四方向移动及休息/工作占位动画；React 角色面板显示精力、当前状态、专业点和背包变化。
6. 游戏循环应有固定模拟步长；不能因 UI 重渲染产生额外奖励。重要操作、每 10 秒和页面隐藏时保存。

验证：npm run lint、npm run test、npm run build；手工观察至少一个角色完整完成“帐篷→3 个目标工作设施→帐篷”的循环。


PROMPT 05 — 角色详情、招募和数据驱动成长
-------------------------------------------
为可玩循环补齐角色管理，并为后续技能/装备/符文建立稳健的数据模型。

要求：
1. 实现角色详情面板：基础属性、耐力经验、采矿/草药学技能、背包、当前建筑和行为队列。
2. 实现简单的原创测试角色招募：从 3 个角色原型中随机抽取，扣除可配置招募券；新角色需要分配帐篷，否则显示待安置状态且不自动工作。
3. 扩展 content 定义：职业原型、技能池、装备槽、装备品质、词条、符文树节点、地区掉落表。只建数据模型和展示占位，不提前实现所有完整玩法。
4. 集中实现并测试属性/经验/资源品质公式，所有可能变动的常量收敛到 balance 配置。
5. 提供开发调试工具（只在开发模式显示）以授予资源、精力归零、加经验；生产构建不能出现该面板。

验证：npm run lint、npm run test、npm run build，并手工测试招募、帐篷分配和刷新后保存。


PROMPT 06 — 地区推进与 Boss 战纵切
-----------------------------------
实现一条完整的地区战斗纵切：派遣、自动小怪推进、Boss 前布阵、自动战斗、结算。不要试图先完成全部职业、装备或多个地区。

要求：
1. 创建一个地区，含 3 波小怪、1 个 Boss 和数据驱动掉落表。至多派遣 5 名角色；正在工作的角色应中断工作，前往工会集合点。
2. 全员到齐后，在主场景中显示非阻塞的横版远征小窗，自动完成小怪阶段；要塞中的未派遣角色持续工作。
3. Boss 前暂停并显示按钮。进入独立 Phaser Boss Scene，提供网格站位区和拖拽布阵；开始后角色自动移动、普攻、按冷却施放 2–3 个示例职业技能。
4. 战斗模拟放在 core，渲染只消费事件。实现生命、伤害、物理/法术减免、闪避、集中值和至少一个治疗技能的最小公式，写核心测试。
5. 胜利后回到要塞，播放箱子/奖励事件并把材料、配方占位、装备占位或招募券写入背包；失败按设计返回要塞且保留 Boss 前进度。
6. Boss 战期间暂停要塞模拟还是继续模拟必须在代码和 UI 中明确；MVP 选择“暂停全局模拟”，避免后台重复结算。

验证：npm run lint、npm run test、npm run build；手工走完一场胜利和一场失败的 Boss 战。


PROMPT 07 — 装备、技能、符文与内容扩展
-----------------------------------------
在已有稳定纵切上，按数据驱动方式扩展中期养成，不修改已通过测试的核心循环。

要求：
1. 实现 11 个装备槽和白/绿/蓝/紫/橙/红品质；装备等级上限 350，基础属性按等级计算，进阶词条按品质配置。
2. 实现同款 3 合 1 升阶；精金锤根据星级提供 1–3 个词条候选；氪金板作为配置化替代材料。红色专属词条、通关后红+1和后续词条规则单独做 feature flag，不要和基础升阶混在一起。
3. 实现五条符文树；普通节点加属性，每 5 个节点允许从候选被动/技能中选一个。符文点、前置关系和重置成本都数据化。
4. 实现职业战斗等级里程碑随机技能获取，以及顿悟设施/顿悟点重随一个技能。应明确随机结果并可测试。
5. 加入至少 2 个新地区、清晰的地区解锁条件和可视化进度。
6. 为存档新增字段提供 schema migration 和旧存档测试。

验证：npm run lint、npm run test、npm run build；手工检查装备升阶、符文解锁、技能重随、旧存档迁移。


PROMPT 08 — 发布质量和试玩平衡
--------------------------------
对 WowManager 做首个公开 GitHub Pages 试玩版的质量收尾，不增加新大系统。

要求：
1. 审查游戏循环、存档、失败提示、键鼠操作、窄屏布局和空状态；修复阻断体验的问题。
2. 加入导出/导入/重置存档的确认流程，并验证损坏文件不会覆盖存档。
3. 用 Playwright 编写核心 E2E：新游戏、建造、自动工作获得资源、刷新恢复、派遣并完成 Boss 战。
4. 优化初始资源加载、贴图组织和画布缩放；确保子路径 /wowmanager/ 下所有资源可用。
5. 检查 GitHub Actions workflow；在 README 写清本地运行、测试、构建、部署与已知限制（仅本地存档、无账号/云同步）。
6. 为所有原创或可用素材加入 ATTRIBUTIONS.md 和许可证说明。删除不使用的调试代码与开发依赖。

验证：npm run lint、npm run test、npm run build、Playwright 测试（如已配置），并用 npm run preview 手工验证构建产物。


每次继续开发前的总提示词（可附加）
--------------------------------------
继续开发当前 WowManager 仓库。先阅读 README 和 docs/ 下全部设计文档，再检查 git status 与现有实现。保持 TypeScript 严格模式，并优先修复与当前任务相关的测试或构建问题。不要覆盖用户已有改动，不要重置 Git 历史，不要添加后端或第三方受版权保护游戏资产。完成后运行 lint、单元测试与生产构建；报告改动、验证和未完成项。
