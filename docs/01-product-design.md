# WowManager 产品与规则设计（v0.1）

## 1. 产品定义

**类型**：像素风 2D 单机网页游戏，融合要塞经营、角色养成、自动生产与 5 人小队战斗。

**首发平台**：桌面浏览器优先，兼容横屏平板；由 GitHub Pages 发布。

**核心循环**：

`建造设施 → 招募/配置角色 → 自动休息与工作 → 获得资源、技能经验和装备 → 组成小队推进地区 → Boss 战/战利品 → 扩建并强化`

游戏采用原创世界观与资产。现阶段的“要塞”“矿坑”等为系统名，不使用任何第三方游戏的美术、音频、剧情或角色。

## 2. MVP 范围

第一可玩版本只实现一条完整、可保存的闭环；其余系统保留数据接口但不先堆内容。

| 系统 | MVP 内容 | 以后扩展 |
| --- | --- | --- |
| 要塞 | 8×8 地块、放置/移动/拆除、一个扩建入口 | 多块区域、地形、装饰、道路 |
| 建筑 | 帐篷、初级矿坑、初级药圃、健身房 | 炼金、锻造、顿悟、符文制造等 |
| 角色 | 3 名测试角色、精力、耐力/力量/敏捷/智力/学识、专业技能 | 职业阶级、随机招募、完整装备池 |
| 自动行为 | 休息补满精力、寻找最近 3 个同类工作设施、完成后返回 | 路径阻挡、优先级、离线结算 |
| 战斗 | 1 个地区、3 波小怪、1 个 Boss、最多 5 人、战前布阵 | 多地区、词缀、地图事件、完整职业技能 |
| 存档 | 单一离线存档、导入/导出/重置 | 账号、云同步、多存档槽 |

## 3. 要塞与建造

### 3.1 格子和建筑

- 初始要塞为 `8 × 8` 可建造格；原点在左上角，每格保存整数坐标 `{ x, y }`。
- 建筑配置包括：`id`、名称、分类、占地宽高、建造成本、可服务角色数、互动配置、精灵资源。
- 放置校验：范围内、未与其他建筑重叠、玩家拥有足够资源。MVP 不做道路和寻路阻挡；角色可直线移动。
- 帐篷初始占地 `1 × 1`，并指定一名拥有者。每名角色必须有一个可用休息建筑。
- 扩建应作为数据驱动的解锁项，而非把 `8 × 8` 写死在渲染逻辑里。

### 3.2 初始建筑配置

以下数值放入数据表，可在平衡阶段调整。未由需求明确的数值标为 **候选值**，不能散落在业务代码中。

| 建筑 | 分类/行动类型 | 时间 | 单轮次数上限 | 每秒精力消耗 | 完成一轮奖励 |
| --- | --- | ---: | ---: | ---: | --- |
| 帐篷 | 休息；可设为制造或锻炼偏好 | 3 秒（候选；已确认休息需要耗时） | — | — | 完整休息结束后恢复至上限 |
| 初级矿坑 | 制造（采集） | 3 秒 | 3 | 1（候选） | 矿石、采矿经验 10 |
| 初级药圃 | 制造（采集） | 3 秒（候选） | 3（候选） | 1（候选） | 草药、草药学经验 10（候选） |
| 健身房 | 锻炼 | 5 秒 | 2 | 1（候选） | 耐力经验 10 |

“制造”是产品中的行动类别；初级矿坑和药圃本质上是采集设施。代码中建议使用 `workType: 'gather' | 'training'`，避免把“制造物品”和“采集”混成同一概念。

## 4. 角色自动行为

### 4.1 状态机

角色状态只有一个主状态，状态切换由游戏模拟层控制：

`IDLE → TO_REST → RESTING → SELECTING_WORK → TO_WORK → WORKING → SELECTING_WORK / TO_REST`

地区战斗派遣时，相关角色转为：

`任意非战斗状态 → TO_GUILD → WAITING_PARTY → EXPEDITION → BOSS_READY → BOSS_BATTLE → TO_REST`

### 4.2 精力与工作选择规则

1. 角色精力为空时，取消当前工作并走向分配给自己的帐篷。
2. 抵达帐篷后进入休息计时，完整休息结束才恢复至最大精力；当前时长为集中配置的 3 秒候选值。帐篷的行动偏好为“制造”或“锻炼”。
3. 系统从该帐篷起，按曼哈顿距离 `|dx| + |dy|` 找出同类、可用的最近 3 座建筑；距离相同则按建筑 ID 排序，保证结果可复现。
4. 本次精力周期内，角色依次使用这 3 座建筑，每座最多连续完成建筑定义的轮次上限。某设施繁忙或不存在时跳过。
5. 若开始下一轮所需精力不足（`每秒消耗 × 互动时长`），不启动该轮，直接返回帐篷。互动只在整轮结束时结算物品和经验。
6. 三座均处理完成后，即使尚有精力也返回帐篷；下一周期重新查找最近 3 座。

**MVP 约定**：初始精力上限为 `30`（候选值）。角色移动本身不消耗精力。精力只在互动计时中按秒扣除；断帧时按真实经过时间累积，但每次更新的单步上限为 250ms，防止后台恢复导致动画和状态跳跃失控。

## 5. 成长系统

### 5.1 基础属性

| 属性 | 战斗影响 |
| --- | --- |
| 耐力 | 最大生命值 |
| 力量 | 力量技能伤害、物理伤害减免 |
| 敏捷 | 敏捷技能伤害、移动速度、闪避概率 |
| 智力 | 智力技能伤害、法术伤害减免 |
| 学识 | 学识技能/治疗强度、战斗中集中值获取速度 |

数值公式集中写在 `src/game/core/formulas/`，由单元测试覆盖。MVP 先用明确、可读的线性/软上限公式；平衡性以配置表修正，不在 UI 组件中计算。

### 5.2 专业与锻炼经验

- 专业技能：采矿、草药学、炼金术等；初版实现采矿和草药学，技能点上限 `300`。
- 锻炼属性：初版实现耐力；无等级上限。
- 当前技能点为 `L` 时，升至 `L + 1` 需要的经验：

```text
xpToNext(L) = 100 × (floor(L / 50) + 1)
```

因此 0–49 点每点 100 经验，50–99 点每点 200 经验，依此递增。专业技能在 300 点时停止获得点数（是否继续累计经验由后续决定；MVP 不累计）。

### 5.3 资源品质

初级矿坑只产出铜矿石、铁矿石和稀有银矿石；药圃同理保留可配置掉落表。每条掉落表应按专业技能区间给出 1/2/3 星品质权重，而不是在代码中写概率。

示例（仅用于 MVP 验证的候选平衡值）：

| 采矿点 | 1 星 | 2 星 | 3 星 |
| --- | ---: | ---: | ---: |
| 0–49 | 75% | 23% | 2% |
| 50–149 | 55% | 38% | 7% |
| 150–249 | 35% | 50% | 15% |
| 250–300 | 20% | 55% | 25% |

先抽矿种，再按技能点抽品质；所有随机数通过可注入 RNG 生成，便于测试与日后加入种子回放。

### 5.4 符文、技能与装备（第二阶段）

- **符文**：五条线（耐力、力量、敏捷、智力、学识）；第 1–4、6–9…节点提供属性，第 5、10…节点从该线技能候选中选择一个。消耗符文点，前置关系以树数据定义。
- **职业技能**：角色所属职业和战斗等级决定可抽卡池；达到里程碑时从候选技能中随机获得一个。顿悟设施解锁后，消耗顿悟点可重随指定技能。
- **装备槽**：头、肩、胸、腿、手套、武器、饰品×2、戒指×2、项链，共 11 槽。
- **装备**：等级上限 350；白/绿/蓝/紫/橙/红品质，基础属性随装备等级，进阶词条随品质。3 件同款上一阶装备合成升阶；精金锤按星级提供 1–3 个词条候选；氪金板为另一升阶材料。红色专属词条和红+1规则作为后续独立里程碑实现。

## 6. 地区与战斗

### 6.1 地区推进

- 玩家选择至多 5 名空闲角色派遣至一个地区。
- 被派遣角色立刻放下工作，移动至工会集合点；全部到齐后进入横版自动推进。
- 小怪阶段在要塞主画面底部/侧边的“远征小窗”中自动演出，不阻挡其他角色在要塞工作。
- 遇到最终 Boss 时暂停，显示“进入 Boss 战”按钮。点击后切换至全屏战斗场景。
- Boss 胜利后，回到要塞并播放胜利与宝箱掉落；失败则返回要塞，地区进度保留至 Boss 前（MVP 约定）。

### 6.2 Boss 战 MVP

1. 进入前为玩家提供网格化站位区，可拖动己方角色到位置，不能重叠。
2. 点击开始后，角色自动向目标移动、普攻并按技能冷却施放技能；不做实时手动施法。
3. 战斗使用固定更新步长（例如 100ms），渲染和规则分离。伤害数字、受击闪烁、投射物、施法动画均为表现层事件。
4. 胜负由 Boss/己方生命状态决定。奖励由地区掉落表生成：制造材料、配方、装备、职业招募券。

首版职业只需要 3 个示例职业和每个 2–3 个技能，验证力量/敏捷/智力/学识的不同作用。完整 1/2/3 阶职业体系在战斗原型稳定后再进入制作。

## 7. 界面和美术原则

- 整体采用低分辨率画布渲染后整数倍放大（建议原始 320×180 或 480×270），CSS 使用 `image-rendering: pixelated`，避免像素插值模糊。
- 主界面：中间要塞画布；顶部资源/时间；右侧角色和建筑检查器；底部活动队列/地区推进；覆盖层放置建造、角色详情、背包、Boss 战。
- 最小动画集：待机、四方向移动、采集/锻炼、近战攻击、远程投射、施法、受击、死亡、宝箱开启。
- 所有素材须记录来源和许可证；开发期可用原创色块/临时占位精灵，之后统一替换。

## 8. 尚待产品确认的数值

这些问题会显著影响节奏，第一版应先以候选配置运行并在试玩后锁定：

1. 初始精力上限、休息的最终时长、每次设施互动是否总是产出 1 件。休息需要时间已经确认。
2. 角色初始数量、招募成本与角色职业分布。
3. 建筑建造/扩建成本，建筑是否有同时使用人数限制。
4. 每个矿种的掉落权重及品质对价值、配方、战斗材料的具体作用。
5. 基础属性的精确战斗公式、集中值上限与技能消耗。
6. 失败惩罚、地区解锁条件、离线收益是否需要。

在这些未锁定前，必须使用 `data/balance/*.ts` 配置，不把候选数值视为最终规则。
